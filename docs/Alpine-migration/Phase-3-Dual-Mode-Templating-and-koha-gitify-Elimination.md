# Phase 3: Dual-Mode Templating & `koha-gitify` Elimination

## Roadmap reference

[Alpine-deeper-integration.md](Alpine-deeper-integration.md) — Phase 3 section.

---

## 0. What Phase 3 Must Achieve

The roadmap defines two deliverables:

1. **Action**: update `koha-conf-site.xml.in` and Apache site templates to accept a dynamic `KOHA_PATH` variable, so the correct paths for dev (`/kohadevbox/koha`) and prod (`/usr/share/koha`) are rendered in a single pass with no post-processing.
2. **Validation**: `dev-runtime` points directly to `/kohadevbox/koha` and `prod-runtime` points to `/usr/share/koha` without any post-boot rewrites.

Eliminating `koha-gitify` is the mechanism: if the template renders correctly the first time, nothing needs to be rewritten afterward.

## 2. Work Items (Strict Sequence)

### Step 3.1 — Introduce `KOHA_PATH` into `run.sh` environment

**File**: `files-alpine/run.sh`

Add a `KOHA_PATH` detection block after the early source validation check (`about.pl`), before any `envsubst` template rendering calls:

```bash
# Phase 3: set KOHA_PATH for dual-mode template rendering
if [ -f "${BUILD_DIR}/koha/about.pl" ] && [ -d "${BUILD_DIR}/koha/koha-tmpl" ]; then
    export KOHA_PATH="${BUILD_DIR}/koha"      # dev: live bind-mounted source
else
    export KOHA_PATH="/usr/share/koha"        # prod: build-time staged assets
fi
export KOHA_LIB_PATH="${KOHA_PATH}/lib"
```

Add `KOHA_PATH` and `KOHA_LIB_PATH` to the `VARS_TO_SUB` construction so `envsubst` substitutes them in all templates.

**Constraint**: this block must appear before the first `envsubst` call in `run.sh` (currently around line 220).

### Step 3.2 — Dual-mode `koha-conf-site.xml.in`

**File**: `files-alpine/templates/koha-conf-site.xml.in`

Replace every hardcoded `/usr/share/koha/intranet/htdocs/intranet-tmpl/…` XSLT path that `koha-gitify` currently rewrites post-boot with `${KOHA_PATH}`-relative tokens:

| Current value | Replace with |
| --- | --- |
| `/usr/share/koha/intranet/htdocs/intranet-tmpl/prog/en/xslt/MARC21slim*.xsl` | `${KOHA_PATH}/koha-tmpl/intranet-tmpl/prog/en/xslt/MARC21slim*.xsl` |

### Step 3.3 — Add project-owned Apache vhost template (`koha-vhost.conf.in`)

**New file**: `files-alpine/templates/koha-vhost.conf.in`

This replaces the `koha-create`-generated vhost + `koha-gitify` rewrite with a single `envsubst` pass. The template must contain every directive that `koha-gitify` currently injects, using `${KOHA_PATH}` and env vars already in `VARS_TO_SUB`:

```apache
# Intranet VirtualHost
<VirtualHost *:${KOHA_INTRANET_PORT}>
    ServerName  ${KOHA_INTRANET_FQDN}
    DocumentRoot ${KOHA_PATH}/koha-tmpl/intranet-tmpl
    ScriptAlias  /cgi-bin/koha/ ${KOHA_PATH}/
    SetEnv KOHA_CONF /etc/koha/sites/${KOHA_INSTANCE}/koha-conf.xml
    SetEnv PERL5LIB  ${KOHA_PATH}:${KOHA_PATH}/lib
    Include /etc/koha/apache-shared-intranet.conf
    <Directory "${KOHA_PATH}">
        Options +ExecCGI +FollowSymlinks
        AddHandler cgi-script .pl
        Require all granted
    </Directory>
    ErrorLog  /var/log/koha/${KOHA_INSTANCE}/intranet-error.log
    CustomLog /var/log/koha/${KOHA_INSTANCE}/intranet-access.log combined
</VirtualHost>

# OPAC VirtualHost
<VirtualHost *:${KOHA_OPAC_PORT}>
    ServerName  ${KOHA_OPAC_FQDN}
    DocumentRoot ${KOHA_PATH}/koha-tmpl/opac-tmpl
    ScriptAlias  /cgi-bin/koha/opac/ ${KOHA_PATH}/opac/
    SetEnv KOHA_CONF /etc/koha/sites/${KOHA_INSTANCE}/koha-conf.xml
    SetEnv PERL5LIB  ${KOHA_PATH}:${KOHA_PATH}/lib
    Include /etc/koha/apache-shared-opac.conf
    <Directory "${KOHA_PATH}">
        Options +ExecCGI +FollowSymlinks
        AddHandler cgi-script .pl
        Require all granted
    </Directory>
    ErrorLog  /var/log/koha/${KOHA_INSTANCE}/opac-error.log
    CustomLog /var/log/koha/${KOHA_INSTANCE}/opac-access.log combined
</VirtualHost>
```

Note: the `Options +ExecCGI` / `AddHandler cgi-script .pl` directives here replace the runtime `sed` injections currently applied to `apache-shared-*-git.conf` in `run.sh` (~L671). Those `sed` calls must also be removed in Step 3.5.

### Step 3.4 — Add `render_vhost` function in `run-sh-alpine.sh`

**File**: `files-alpine/lib/run-sh-alpine.sh`

```bash
render_vhost() {
    local instance=$1
    local target_dir=/etc/apache2/sites-available
    mkdir -p "${target_dir}"
    envsubst "${VARS_TO_SUB}" \
        < "${BUILD_DIR}/templates/koha-vhost.conf.in" \
        > "${target_dir}/${instance}.conf"
    chmod 644 "${target_dir}/${instance}.conf"
}
```

`VARS_TO_SUB` is available in the calling scope from `run.sh`. The function must be added before it is called in Step 3.5.

### Step 3.6 — Remove `--gitify_dir` from the `do_all_you_can_do.pl` call (Stage D)

**File**: `files-alpine/run.sh` (~L630)

Remove `--gitify_dir ${BUILD_DIR}/gitify` from the `do_all_you_can_do.pl` invocation. That argument is forwarded internally to `cp_debian_files.pl --gitify_dir=…` which triggers another `koha-gitify` run. Removing it at the call site propagates the absence through the entire Stage D chain.

**Risk**: verify that `do_all_you_can_do.pl` does not die when `--gitify_dir` is absent or points to a non-existent path. If it does, add `--skip-gitify` support to `cp_alpine_files.pl` as a secondary guard.

## 6. Risks and Mitigations

| Risk | Mitigation |
| --- | --- |
| `do_all_you_can_do.pl` may die when `--gitify_dir` is absent | Verify behavior before removing the argument; add `--skip-gitify` guard to `cp_alpine_files.pl` as fallback |
| `koha-conf-site.xml.in` XSLT path substitution breaks Zebra stylesheet lookups | Audit every `/usr/share/koha/intranet/htdocs/…` reference in the template and confirm the dev path `/kohadevbox/koha/koha-tmpl/intranet-tmpl/…` resolves correctly |
| `koha-create` generates its own vhost that collides with `render_vhost` output | Call `render_vhost` strictly after `koha-create` so it overwrites the generated file; or suppress vhost generation in `koha-create` via a flag |
| `KOHA_PATH` must be exported before the first `envsubst` call in `run.sh` | Confirm placement of Step 3.1 block is before line ~220 in the current `run.sh` |
| Alpine CGI directives currently injected via runtime `sed` into `apache-shared-*-git.conf` will lose their target file | Those `Options +ExecCGI` and `AddHandler` directives are moved into `koha-vhost.conf.in` (Step 3.3); the runtime `sed` block must be removed in the same commit as Step 3.5 |
