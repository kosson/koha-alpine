# 2026-08-03 - Prod image size reduction and runtime node_modules verification

## Session summary

This session investigated why the production image was nearly 6 GB, implemented a safe optimization patch, rebuilt the image, and verified runtime behavior.

Key outcomes:

1. Production image size reduced from 5.96 GB to 2.00 GB.
2. Root cause was confirmed as build cache and dev/build artifacts retained in final layers, not primarily Koha git metadata.
3. Runtime verification showed node_modules is not required in the current prod flow.

## Initial problem

The production image `kosson/koha-alpine-prod:25.11.06-1` was observed at 5.96 GB.

The initial hypothesis was that `/kohadevbox/koha/.git` might be responsible.

## Investigation and findings

### 1) Git metadata was not the main cause

Measured inside the original image:

- `/kohadevbox/koha/.git` was about 28 MB.

Conclusion: `.git` contributed, but it was not a major size driver.

### 2) Main size contributors were caches and build artifacts

Measured inside the original image:

- `/usr/local/share/.cache/yarn` about 1.2 GB
- `/root/.cache/Cypress` about 662 MB
- `/root/.cpanm/work` about 494 MB
- `/kohadevbox/koha/node_modules` about 626 MB

Additional contributor:

- `/kohadevbox/misc4dev` about 128 MB

Layer history also showed large layers in prod runtime around yarn/build steps.

## Implementation changes

### A) Prod ref robustness improvement

`stack-alpine.sh` was adjusted to normalize release-like refs so values like `25.11.06-1` become `v25.11.06-1` in prod mode.

This fixed the earlier fetch failure:

- `fatal: couldn't find remote ref 25.11.06-1`

### B) Documentation correction

README production build example was corrected to use `--koha-ref v25.11.06-1`.

### C) Dockerfile size optimization

`Dockerfile-Alpine` was updated to remove transient build data from final image layers:

1. Added CPAN work cache cleanup in CPAN install layers.
2. Combined prod yarn install, asset staging, and cleanup in one RUN layer.
3. Set `CYPRESS_INSTALL_BINARY=0` for the prod yarn install step.
4. Removed from final prod layer after staging:
   - `/kohadevbox/koha/node_modules`
   - `/kohadevbox/koha/.git`
   - yarn/npm/cpanm/root caches
   - temporary build leftovers under `/tmp`

## Rebuild and validation

A full production rebuild was run and completed successfully (exit code 0).

Final size check:

- Before: 5.96 GB
- After: 2.00 GB
- Reduction: about 3.96 GB (about 66%)

Post-build runtime footprint checks:

- `.git` absent from `/kohadevbox/koha`
- `node_modules` absent from `/kohadevbox/koha`
- Cypress cache absent
- `/usr/local/share/.cache` reduced to minimal footprint
- `/root/.cpanm` reduced to minimal footprint

## Runtime node_modules verification

Question checked: are `node_modules` required by Koha at runtime in this production flow?

Answer: no, not in the current prod path.

Why:

1. Prod runtime uses pre-staged assets and skips runtime asset copy (`SKIP_RUNTIME_ASSET_COPY=yes`).
2. Prod runtime skips runtime yarn install (`SKIP_YARN_INSTALL=yes`).
3. `PATH` entries referencing node_modules are non-fatal if directories are absent.
4. Cypress linking/chown logic is best-effort and non-fatal.

Observed behavior remained consistent with successful prod image build and runtime checks.

## Residual notes

1. `misc4dev` remains in the shared base and still costs about 128 MB in prod image.
2. A future hardening pass can split builder/runtime concerns further to remove dev-only trees from prod-runtime.
